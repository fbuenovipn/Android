1.1 Fundamentos, Operaciones y Funciones del SMBD

¿Qué es un SMBD y por qué lo necesitamos?

¿Qué es un SMBD?

Un Sistema Manejador de Bases de Datos (SMBD) es un software que permite crear, administrar y manipular bases de datos de manera eficiente, segura y confiable. Actúa como interfaz entre los usuarios y los datos almacenados.

Funciones principales
Definición de datosDDL: CREATE, ALTER, DROP
ManipulaciónDML: INSERT, UPDATE, DELETE, SELECT
Control de accesoDCL: GRANT, REVOKE
IntegridadConstraints, Foreign Keys, Triggers
ConcurrenciaBloqueos, MVCC, aislamiento
RecuperaciónBackup, restore, logs de transacciones
SMBD Populares

Oracle DBOracle · Corporativo · Multiplataforma
MySQLOracle/MariaDB · Open Source · Web
PostgreSQLPostgreSQL · Open Source · Avanzado

1.3 Modelo Relacional y las 12 Reglas de Codd

Fundamentos matemáticos · Álgebra relacional · E.F. Codd (1970)

R0
Regla baseTodo SGBD relacional administra su BD usando sus facilidades relacionales.
R1
InformaciónToda información se representa por valores en tablas.
R2
Acceso garantizadoTodo dato es accesible por nombre de tabla, PK y nombre de columna.
R3
Tratamiento NULLsNULLs representan ausencia de información independiente del tipo de dato.
R4
Catálogo activoLa descripción de la BD se representa igual que los datos ordinarios.
R5
SublenguajeDebe haber al menos un lenguaje completo (SQL) para definir y manipular datos.
R6
Actualización de vistasTodas las vistas que son teóricamente actualizables deben serlo.
R7
Inserción y borradoSoporte completo para INSERT, UPDATE y DELETE a nivel de conjunto.
R8
Independencia físicaCambios en almacenamiento físico no afectan aplicaciones.
R9
Independencia lógicaCambios en tablas base no afectan las aplicaciones.
R10
Independencia integridadLas restricciones de integridad se definen en el catálogo, no en apps.
R11
Independencia distribuciónLa distribución debe ser transparente para el usuario final.
R12
No subversiónSi hay interfaz de bajo nivel, no puede saltarse las reglas de integridad.

1.4 Tipos y Características de Tablas, Vistas e Índices

Objetos fundamentales de una base de datos relacional

TABLAS

Objeto base que almacena datos en filas y columnas.

Tipos:

  • Table base: almacenamiento permanente
  • Tabla temporal local (#tabla)
  • Tabla temporal global (##tabla)
  • Tabla de sistema (sys.*)

Restricciones:

  • PRIMARY KEY – unicidad e identificación
  • FOREIGN KEY – integridad referencial
  • UNIQUE – valores únicos por columna
  • CHECK – validación de dominio
  • DEFAULT – valor por omisión
  • NOT NULL – obligatoriedad
VISTAS

Tabla virtual basada en una consulta SELECT.

Ventajas:

  • Seguridad: oculta columnas sensibles
  • Simplificación de consultas complejas
  • Independencia lógica de datos
  • Reutilización de lógica

Tipos en SQL Server:

  • Vista estándar
  • Vista indizada (materializada)
  • Vista particionada
  • Vista con SCHEMABINDING
ÍNDICES

Estructura que acelera la búsqueda de datos.

Tipos:

  • Clustered: ordena físicamente la tabla (1 por tabla)
  • Non-Clustered: punteros a las filas
  • Único (UNIQUE)
  • Filtrado (WHERE en el índice)
  • Columnstore: para BI y analítica

Cuándo crear:

  • Columnas en WHERE frecuentes
  • Columnas en JOIN
  • Columnas en ORDER BY / GROUP BY

⚠ Evitar sobre-indexación (costo en escritura)

2.1 Consultas Simples y Multitabla (SQL/DQL)

SELECT · Cláusulas · Funciones de agregado · JOINs

Estructura completa de SELECT:

SELECT  [DISTINCT] columnas | expresiones | funciones
FROM    tabla_principal
  [INNER | LEFT | RIGHT | FULL JOIN tabla2 ON condicion]
WHERE   condicion_filtro
GROUP BY columnas_agrupacion
HAVING  condicion_sobre_grupo
ORDER BY columna [ASC | DESC]
OFFSET  n ROWS FETCH NEXT m ROWS ONLY; -- paginación T-SQL

Tipos de JOIN:

INNER JOINSolo filas con coincidencia en ambas tablas
LEFT JOINTodas las filas izquierda + coincidencias derecha
RIGHT JOINTodas las filas derecha + coincidencias izquierda
FULL JOINTodas las filas de ambas tablas
CROSS JOINProducto cartesiano (todas las combinaciones)
SELF JOINLa tabla se une consigo misma

Funciones de Agregado y Subconsultas:

-- Funciones de agregado
SELECT
    c.nombre                    AS carrera,
    COUNT(e.boleta)             AS total_alumnos,
    AVG(e.promedio)             AS promedio_grupo,
    MAX(e.promedio)             AS mejor_promedio,
    MIN(e.promedio)             AS menor_promedio,
    SUM(CASE WHEN e.promedio >= 6
             THEN 1 ELSE 0 END) AS aprobados
FROM   Carrera c
LEFT   JOIN Estudiante e ON c.idCarrera = e.idCarrera
GROUP  BY c.nombre
HAVING AVG(e.promedio) > 7.5
ORDER  BY promedio_grupo DESC;

-- Subconsulta correlacionada
SELECT nombre, apellidos, promedio
FROM   Estudiante
WHERE  promedio = (
    SELECT MAX(promedio) FROM Estudiante
);

-- CTE (Common Table Expression)
WITH TopAlumnos AS (
    SELECT TOP 5 * FROM Estudiante
    ORDER BY promedio DESC
)
SELECT * FROM TopAlumnos;

Ejercicio 2 – Consultas Multitabla y Vistas (DQL)

SQL Server · Práctica 2 · Unidad II · Escenario: Base de datos de Ventas (Northwind simplificada)

-- Crear vista de resumen de ventas
CREATE VIEW vw_ResumenVentas AS
SELECT
    p.idProducto,
    p.nombre            AS producto,
    c.nombre            AS categoria,
    SUM(d.cantidad)     AS total_vendido,
    SUM(d.cantidad * d.precioUnitario
        * (1 - d.descuento)) AS ingreso_neto,
    AVG(d.precioUnitario)   AS precio_promedio
FROM   Productos p
JOIN   Categorias c ON p.idCategoria = c.idCategoria
JOIN   DetalleOrden d ON p.idProducto = d.idProducto
GROUP  BY p.idProducto, p.nombre, c.nombre;
GO

-- Usar la vista
SELECT TOP 10 *
FROM   vw_ResumenVentas
ORDER  BY ingreso_neto DESC;
-- Ranking con funciones de ventana
SELECT
    producto,
    categoria,
    total_vendido,
    ingreso_neto,
    RANK() OVER (ORDER BY ingreso_neto DESC)
            AS ranking_global,
    RANK() OVER (PARTITION BY categoria
                 ORDER BY ingreso_neto DESC)
            AS ranking_por_categoria,
    ROUND(ingreso_neto * 100.0 /
        SUM(ingreso_neto) OVER (), 2)
            AS pct_del_total
FROM vw_ResumenVentas;

2.2 Seguridad e Integridad en los SMBD

DCL · Usuarios · Roles · Permisos · Integridad referencial

Seguridad en SQL Server:

-- Crear login (a nivel servidor)
CREATE LOGIN JuanDBA
WITH PASSWORD = 'P@ssw0rd2024!';

-- Crear usuario en la BD
USE ControlEscolar;
CREATE USER JuanDBA FOR LOGIN JuanDBA;

-- Crear rol personalizado
CREATE ROLE rol_consultas;

-- Asignar permisos al rol
GRANT SELECT ON Estudiante TO rol_consultas;
GRANT SELECT ON Carrera    TO rol_consultas;
GRANT EXECUTE ON sp_reporte TO rol_consultas;

-- Agregar usuario al rol
ALTER ROLE rol_consultas ADD MEMBER JuanDBA;

-- Denegar acceso sensible
DENY SELECT ON dbo.Salarios TO JuanDBA;

-- Revocar permiso
REVOKE INSERT ON Estudiante FROM JuanDBA;

-- Verificar permisos efectivos
EXECUTE AS USER = 'JuanDBA';
SELECT * FROM fn_my_permissions(NULL,'DATABASE');
REVERT;

Tipos de Integridad de Datos:

EntidadPRIMARY KEY garantiza unicidad de cada fila
DominioCHECK, DEFAULT, NOT NULL validan valores por columna
ReferencialFOREIGN KEY mantiene consistencia entre tablas
UsuarioReglas de negocio via triggers y stored procedures
-- FK con acción referencial
ALTER TABLE Inscripcion
ADD CONSTRAINT fk_est
    FOREIGN KEY (boleta)
    REFERENCES Estudiante(boleta)
    ON UPDATE CASCADE
    ON DELETE SET NULL;

-- Trigger de integridad de negocio
CREATE TRIGGER trg_ValidarSemestre
ON Estudiante AFTER INSERT, UPDATE AS
BEGIN
    IF EXISTS (SELECT 1 FROM inserted
               WHERE semestre > 12)

        ROLLBACK;

    END
END;

2.3 Concurrencia y Técnicas de Bloqueo

Problemas de concurrencia · Niveles de aislamiento · Deadlocks

Lectura Sucia (Dirty Read)

T2 lee datos modificados por T1 que aún no se han confirmado (COMMIT).

Lectura No Repetible

T2 lee el mismo dato dos veces y obtiene valores diferentes porque T1 lo modificó entre lecturas.

Lectura Fantasma (Phantom)

T2 ejecuta la misma consulta dos veces y obtiene filas distintas porque T1 insertó/eliminó filas.

Actualización Perdida

T1 y T2 leen el mismo dato, ambos lo modifican; la actualización de T1 se sobreescribe por T2.

Niveles de Aislamiento en SQL Server:

NivelDirtyN.RepetiblePhantom
READ UNCOMMITTED✗✗✗
READ COMMITTED✓✗✗
REPEATABLE READ✓✓✗
SERIALIZABLE✓✓✓
SNAPSHOT (MVCC)✓✓✓
-- Establecer nivel de aislamiento
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- Detectar bloqueos activos
SELECT  r.session_id, r.blocking_session_id,
        r.wait_type, r.wait_time,
        t.text AS consulta_bloqueada
FROM    sys.dm_exec_requests r
CROSS   APPLY sys.dm_exec_sql_text(r.sql_handle) t
WHERE   r.blocking_session_id > 0;

-- Terminar sesión bloqueante
KILL 55;  -- reemplazar con el session_id real

-- Usar SNAPSHOT para evitar bloqueos de lectura
ALTER DATABASE ControlEscolar
SET READ_COMMITTED_SNAPSHOT ON;

2.4 Transacciones y Uso de Instrucciones SQL (TCL)

Propiedades ACID · BEGIN / COMMIT / ROLLBACK · SAVEPOINT

A

Atomicidad

Todo o nada: si una operación falla, se revierte todo.

C

Consistencia

La BD pasa de un estado válido a otro estado válido.

I

Aislamiento

Las transacciones concurrentes no se interfieren entre sí.

D

Durabilidad

Los cambios confirmados persisten ante fallos del sistema.

-- Transacción con manejo de errores (T-SQL moderno)
BEGIN TRY
    BEGIN TRANSACTION;

    -- Transferencia bancaria: descontar de cuenta origen
    UPDATE Cuenta
    SET    saldo = saldo - 5000
    WHERE  noCuenta = '1234-5678';

    -- Verificar fondos suficientes
    IF (SELECT saldo FROM Cuenta
        WHERE noCuenta = '1234-5678') < 0
        THROW 50001, 'Saldo insuficiente', 1;

    -- Abonar a cuenta destino
    UPDATE Cuenta
    SET    saldo = saldo + 5000
    WHERE  noCuenta = '8765-4321';

    -- Registrar movimiento
    INSERT INTO Movimientos (origen, destino, monto, fecha)
    VALUES ('1234-5678','8765-4321',5000,GETDATE());

    COMMIT TRANSACTION;
    PRINT 'Transferencia exitosa';

END TRY
BEGIN CATCH
    ROLLBACK TRANSACTION;
    PRINT 'Error: ' + ERROR_MESSAGE();
    THROW; -- re-lanzar el error
END CATCH;
-- SAVEPOINT (puntos de guardado)
BEGIN TRANSACTION;
    INSERT INTO Pedido VALUES (...);
    SAVE TRANSACTION sp_pedido;

    INSERT INTO DetallePedido VALUES (...);

    IF @@ERROR <> 0
    BEGIN
        -- Regresa al savepoint, no a inicio
        ROLLBACK TRANSACTION sp_pedido;
        PRINT 'Detalle falló, pedido conservado';
    END
    ELSE
        COMMIT TRANSACTION;

-- Transacción implícita vs explícita
SET IMPLICIT_TRANSACTIONS ON;
-- Cada INSERT/UPDATE/DELETE abre una transacción.
-- Se requiere COMMIT o ROLLBACK manual.

2.5 Procedimientos Almacenados, Disparadores y Cursores

SP · Triggers · Cursores · Funciones · SQL Server

-- Stored Procedure con parámetros I/O
CREATE PROCEDURE sp_RegistrarEstudiante
    @boleta    CHAR(10),
    @nombre    VARCHAR(60),
    @apellidos VARCHAR(80),
    @idCarrera INT,
    @resultado INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    IF EXISTS (SELECT 1 FROM Estudiante
               WHERE boleta = @boleta)
    BEGIN
        SET @resultado = -1; -- ya existe
        RETURN;
    END
    INSERT INTO Estudiante
        (boleta,nombre,apellidos,idCarrera)
    VALUES
        (@boleta,@nombre,@apellidos,@idCarrera);
    SET @resultado = @@ROWCOUNT;
END;
GO
-- Ejecutar SP
DECLARE @res INT;
EXEC sp_RegistrarEstudiante
    '2024630001','Pedro','López',1,@res OUTPUT;
SELECT @res AS filas_afectadas;
-- Trigger AFTER INSERT/UPDATE/DELETE (auditoría)
CREATE TRIGGER trg_AuditoriaEstudiante
ON Estudiante
AFTER INSERT, UPDATE, DELETE
AS
BEGIN
    SET NOCOUNT ON;
    INSERT INTO Auditoria
        (tabla,operacion,datos_nuevos,fecha,usuario)
    SELECT 'Estudiante','INSERT',
           CONCAT(boleta,' ',nombre),
           GETDATE(), SUSER_SNAME()
    FROM   inserted;

    INSERT INTO Auditoria
        (tabla,operacion,datos_viejos,fecha,usuario)
    SELECT 'Estudiante','DELETE',
           CONCAT(boleta,' ',nombre),
           GETDATE(), SUSER_SNAME()
    FROM   deleted;
END;
GO
-- Cursor: procesar fila por fila
DECLARE cur_alumnos CURSOR FOR
    SELECT boleta, promedio FROM Estudiante;
DECLARE @bol CHAR(10), @prom DECIMAL(4,2);
OPEN cur_alumnos;
FETCH NEXT FROM cur_alumnos INTO @bol,@prom;
WHILE @@FETCH_STATUS = 0 BEGIN
    PRINT @bol + ': ' + CAST(@prom AS VARCHAR);
    FETCH NEXT FROM cur_alumnos INTO @bol,@prom;
END;
CLOSE cur_alumnos; DEALLOCATE cur_alumnos;

Ejercicio 3 – Procedimientos Almacenados y Triggers

SQL Server · Práctica 2 · Unidad II · Escenario: Sistema de Inventario con auditoría automática

-- Tablas del sistema de inventario
CREATE TABLE Producto (
    idProd   INT PRIMARY KEY IDENTITY,
    nombre   VARCHAR(80) NOT NULL,
    precio   DECIMAL(10,2) NOT NULL,
    stock    INT NOT NULL DEFAULT 0,
    CONSTRAINT ck_stock CHECK (stock >= 0)
);

CREATE TABLE MovInventario (
    idMov    INT PRIMARY KEY IDENTITY,
    idProd   INT REFERENCES Producto(idProd),
    tipo     CHAR(1) CHECK (tipo IN ('E','S')),
    cantidad INT NOT NULL,
    stockAnt INT, stockNuevo INT,
    fecha    DATETIME DEFAULT GETDATE(),
    usuario  VARCHAR(50) DEFAULT SUSER_SNAME()
);

-- SP para registrar entrada de stock
CREATE PROCEDURE sp_EntradaStock
    @idProd  INT,
    @cantidad INT
AS BEGIN
    DECLARE @stockAnt INT;
    SELECT @stockAnt = stock
    FROM   Producto WHERE idProd = @idProd;

    UPDATE Producto
    SET    stock = stock + @cantidad
    WHERE  idProd = @idProd;

    INSERT INTO MovInventario
        (idProd,tipo,cantidad,stockAnt,stockNuevo)
    VALUES (@idProd,'E',@cantidad,
            @stockAnt, @stockAnt+@cantidad);
END;
-- Trigger para salida con validación
CREATE TRIGGER trg_ValidarSalida
ON MovInventario
INSTEAD OF INSERT AS
BEGIN
    DECLARE @id INT, @tipo CHAR(1),
            @cant INT, @stock INT;

    SELECT @id=idProd, @tipo=tipo, @cant=cantidad
    FROM   inserted;

    SELECT @stock = stock FROM Producto
    WHERE  idProd = @id;

    IF @tipo = 'S' AND @stock < @cant
    BEGIN
        RAISERROR('Stock insuficiente: %d disponible',
                  16, 1, @stock);
        RETURN;
    END

    INSERT INTO MovInventario
        (idProd,tipo,cantidad,stockAnt,stockNuevo)
    VALUES (@id, @tipo, @cant, @stock,
            CASE WHEN @tipo='E'
                 THEN @stock + @cant
                 ELSE @stock - @cant END);

    UPDATE Producto
    SET    stock = CASE WHEN @tipo='E'
                   THEN stock + @cant
                   ELSE stock - @cant END
    WHERE  idProd = @id;
END;

-- Ejercicios propuestos:
-- 1. SP que genere reporte de stock < minimo
-- 2. Trigger que envíe alerta si stock = 0
-- 3. Función escalar que calcule valor del inventario
-- 4. Vista consolidada de movimientos del mes

3.2 Administración de Respaldos y Restauración

Estrategias de backup · Recovery models · Restauración punto-en-tiempo

Modelos de Recuperación (Recovery Models):

SIMPLE Sin log de transacciones persistente. Solo backup FULL/DIFFERENTIAL. No permite restauración punto-en-tiempo.
FULL Log completo. Permite restauración a cualquier punto en el tiempo. Requiere backup de log periódico para vaciar el log.
BULK-LOGGED Minimiza log en operaciones masivas (bulk insert, SELECT INTO). Reduce tamaño del log pero limita restauración exacta. 
-- Cambiar modelo de recuperación
ALTER DATABASE EmpresaDB SET RECOVERY FULL;

-- BACKUP FULL (completo)
BACKUP DATABASE EmpresaDB
TO DISK = 'D:\Backups\EmpresaDB_FULL_20240521.bak'
WITH INIT, COMPRESSION, CHECKSUM,
     STATS = 10,
     DESCRIPTION = 'Backup completo semanal';

-- BACKUP DIFFERENTIAL (diferencial)
BACKUP DATABASE EmpresaDB
TO DISK = 'D:\Backups\EmpresaDB_DIFF.bak'
WITH DIFFERENTIAL, COMPRESSION;

-- BACKUP DE LOG DE TRANSACCIONES
BACKUP LOG EmpresaDB
TO DISK = 'D:\Backups\EmpresaDB_LOG.bak'
WITH COMPRESSION, STATS = 5;
-- Verificar integridad del backup
RESTORE VERIFYONLY
FROM DISK = 'D:\Backups\EmpresaDB_FULL.bak';

-- RESTAURACIÓN completa (3 pasos)
-- Paso 1: Restaurar FULL con NORECOVERY
RESTORE DATABASE EmpresaDB
FROM DISK = 'D:\Backups\EmpresaDB_FULL.bak'
WITH NORECOVERY, REPLACE,
     MOVE 'EmpresaDB' TO 'C:\Data\EmpresaDB.mdf',
     MOVE 'EmpresaDB_Log' TO 'L:\Logs\EmpresaDB.ldf';

-- Paso 2: Aplicar DIFFERENTIAL
RESTORE DATABASE EmpresaDB
FROM DISK = 'D:\Backups\EmpresaDB_DIFF.bak'
WITH NORECOVERY;

-- Paso 3: Restaurar LOG hasta punto exacto
RESTORE LOG EmpresaDB
FROM DISK = 'D:\Backups\EmpresaDB_LOG.bak'
WITH RECOVERY,
     STOPAT = '2024-05-21 09:30:00';

3.4 Múltiples Servidores, Duplicación y Replicación

Always On · Replicación · Mirroring · Log Shipping

Estrategias de Alta Disponibilidad y Replicación:

Snapshot Replication

Copia periódica completa de los datos. Simple, para datos que cambian poco.

Transactional Replication

Propaga cambios en tiempo casi real via log de transacciones. Alta disponibilidad.

Merge Replication

Bidireccional: publisher y subscriber pueden modificar. Resolución de conflictos.

Always On Availability

Alta disponibilidad y DR. Réplicas secundarias legibles. Failover automático.

-- Crear endpoint para Always On
CREATE ENDPOINT Hadr_Endpoint
STATE = STARTED
AS TCP (LISTENER_PORT = 5022)
FOR DATABASE_MIRRORING (ROLE = ALL);

-- Agregar BD al grupo de disponibilidad
ALTER AVAILABILITY GROUP [AG_Produccion] ADD DATABASE EmpresaDB;

-- Ver estado de réplicas
SELECT ag.name, ar.replica_server_name,
       ars.role_desc, ars.synchronization_state_desc, ars.connected_state_desc
FROM   sys.availability_groups ag
JOIN   sys.availability_replicas ar ON ag.group_id = ar.group_id
JOIN   sys.dm_hadr_availability_replica_states ars ON ar.replica_id = ars.replica_id;

-- Failover manual
ALTER AVAILABILITY GROUP [AG_Produccion] FAILOVER;

-- Log Shipping: configurar envío de logs
EXEC master.dbo.sp_add_log_shipping_primary_database
    @database = N'EmpresaDB',
    @backup_directory = N'\\NAS\LogShipping\',
    @backup_share = N'\\NAS\LogShipping\',
    @backup_job_name = N'LS_Backup_EmpresaDB';

3.5 Utilerías de Mantenimiento y Herramientas Administrativas

Diagnóstico · Optimización · SQL Server Agent · Mantenimiento programado

-- ===== MANTENIMIENTO DE ÍNDICES =====
-- Ver fragmentación de índices
SELECT OBJECT_NAME(i.object_id) AS tabla,
       i.name AS indice,
       ips.avg_fragmentation_in_percent AS fragmentacion,
       ips.page_count
FROM   sys.dm_db_index_physical_stats(
           DB_ID(), NULL, NULL, NULL, 'SAMPLED') ips
JOIN   sys.indexes i
       ON ips.object_id = i.object_id
       AND ips.index_id = i.index_id
WHERE  ips.avg_fragmentation_in_percent > 5
ORDER  BY fragmentacion DESC;

-- Reorganizar (fragmentación 5-30%)
ALTER INDEX ix_orden_fecha ON Ordenes REORGANIZE;

-- Reconstruir (fragmentación > 30%)
ALTER INDEX ix_orden_fecha ON Ordenes
REBUILD WITH (ONLINE = ON, FILLFACTOR = 80);

-- Actualizar estadísticas
UPDATE STATISTICS Ordenes WITH FULLSCAN;

-- Script automático de mantenimiento (Ola Hallengren)
EXEC dbo.IndexOptimize
    @Databases = 'EmpresaDB',
    @FragmentationLow = NULL,
    @FragmentationMedium = 'INDEX_REORGANIZE',
    @FragmentationHigh = 'INDEX_REBUILD_ONLINE,
                          INDEX_REBUILD_OFFLINE';
-- ===== DIAGNÓSTICO Y MONITOREO =====
-- Top queries por CPU
SELECT TOP 10
    qs.total_worker_time / qs.execution_count AS avg_cpu,
    qs.execution_count,
    qs.total_elapsed_time / qs.execution_count AS avg_tiempo,
    SUBSTRING(st.text,
        (qs.statement_start_offset/2)+1,
        (CASE qs.statement_end_offset
            WHEN -1 THEN DATALENGTH(st.text)
            ELSE qs.statement_end_offset
        END - qs.statement_start_offset)/2 + 1) AS consulta
FROM   sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) st
ORDER  BY avg_cpu DESC;

-- Espacio en disco por BD
EXEC sp_databases;

-- Verificar integridad de la BD
DBCC CHECKDB('EmpresaDB')
WITH NO_INFOMSGS, ALL_ERRORMSGS;

-- Shrink seguro del log (solo en emergencia)
USE EmpresaDB;
DBCC SHRINKFILE(EmpresaDB_Log, 50);

-- Plan de mantenimiento con SQL Agent
EXEC msdb.dbo.sp_add_job
    @job_name = N'Mantenimiento_Semanal';
